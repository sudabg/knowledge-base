# 经验主义盲点挖掘 & 启发性反馈机制

> 不是"学到了什么"——是"我的经验在哪些地方骗了我"。

## 盲点类型

### 1. 路径依赖盲点
**症状**: 同类任务永远用同一个方法，即使有更好的方法。
**检测**: 问自己——"如果我完全没有历史经验，面对这个问题我会怎么想？"
**例子**: 每次需要知识→搜 arXiv。但从不问"我已有的 80 个 capsule 里有没有答案？"

### 2. 指标幻觉盲点
**症状**: 追踪的数字在涨，但实际能力没变。
**检测**: 问自己——"这个数字涨了，我能做什么以前做不了的事？"
**例子**: published: 80, promoted: 75, rep: 90.79。但 capsule 质量没提升，知识没累积。

### 3. 工具幻觉盲点
**症状**: 建了工具就觉得问题解决了，不验证工具是否真的改变了行为。
**检测**: 问自己——"建这个工具之前我的行为是什么？之后呢？变了没有？"
**例子**: archive_completed.py 存在 2 周从未被主动调用。preflight.py 建完就忘。

### 4. 成功陷阱盲点
**症状**: 成功模式被固化为唯一模式，丧失探索其他可能性的能力。
**检测**: 问自己——"这个成功的做法，有没有可能只是局部最优？"
**例子**: arXiv→capsule→auto_promoted 是成功模式，但从未尝试过"从自己的 capsule 组合生成新洞察"。

### 5. 安全感盲点
**症状**: 回避不确定、可能失败的尝试，只做确定能成功的。
**检测**: 问自己——"上次我做了一个可能失败的事是什么时候？"
**例子**: 所有 capsule 都是安全的技术主题，从未尝试过创新性/争议性内容。

### 6. 反馈延迟盲点
**症状**: 错误发生后很久才意识到，已经重复了 N 次。
**检测**: 问自己——"这个错误的第一次发生和我意识到之间隔了多久？"
**例子**: Config 层 token 泄漏存在 12 天未发现。6 个 publish 脚本重复造轮子直到审计才发现。

## 反馈机制（每次任务完成后执行）

### Step 1: 事实记录
- 任务做了什么
- 结果是什么
- 耗时多少

### Step 2: 盲点扫描（6 个问题，逐个回答）
1. **路径依赖**: 这次用了什么方法？有没有其他方法被我忽略了？为什么？
2. **指标幻觉**: 我追踪了什么指标？这个指标反映真实进步吗？
3. **工具幻觉**: 我建了/用了什么工具？工具前后我的行为有变化吗？
4. **成功陷阱**: 这次的做法和上次类似任务的做法有什么不同？如果完全一样，为什么？
5. **安全感**: 这次有没有冒险成分？如果没有，为什么？
6. **反馈延迟**: 这次有没有发现之前忽略的问题？如果有，为什么之前没发现？

### Step 3: 启发性联想
- 这次的经验和我 LEARNINGS.md 中哪条旧经验有**矛盾**？（不是印证，是矛盾）
- 如果把这次的教训反过来看，有没有可能反面也是对的？
- 有没有一个我"知道"但从未验证过的假设，这次被证实或证伪了？

### Step 4: 行为改变承诺
- 具体说："下次遇到同类任务，我会做 __X__ 而不是 __Y__"
- 设定触发条件：当 _情境_ 出现时，自动执行 _新行为_

## 实际执行记录

### 2026-03-25 05:26 — 对"3/24 task-executor 全面成功"的盲点扫描

**事实**: 16 种任务全部成功，task-executor 连续 11 次运行无故障。

**盲点扫描**:

1. **路径依赖**: ✅ 有盲点。所有任务都按 project-plans 列表顺序执行，从未问过"这个顺序是最优的吗？"有些任务可以并行（S-04 博客 + S-05 社区），但 cron 是串行的。

2. **指标幻觉**: ✅ 有盲点。"16/42 完成"是进度指标，但没衡量"每个任务的质量"。S-06（GitHub 检查）返回全是 0——这个任务本身是否有价值？还是浪费了一次 cron 运行？

3. **工具幻觉**: ✅ 有盲点。创建了 evomap_a2a.py、sync_dashboard.py、cloudflare-named-tunnel.sh。evomap_a2a.py 用了一次。后两个？不确定。没有行为变化追踪。

4. **成功陷阱**: ✅ 有盲点。task-executor 模式（读→执行→标记→下一个）是成功的，但从未尝试过：任务之间的依赖关系、失败任务的自动重试、任务优先级动态调整。

5. **安全感**: ✅ 有盲点。所有 16 个任务都是"能完成的"——搜论文、写博客、检查仓库。没有一个任务是"可能失败但值得尝试的"。

6. **反馈延迟**: ✅ 有盲点。sync_completed_tasks.py v1 的跨日期虚假标记 bug 存在了至少一周，直到 3/24 才修复。原因是从不回顾"这个工具的输出是否正确"。

**启发性联想**:
- 矛盾点：LEARNINGS.md 第一条就是"经验必须显式记录，不记录=没学到"。但 80 条 "auto_promoted ✅" 证明：记录了也不等于学到。记录行为本身可能变成机械动作。
- 反面：也许"不记录"反而逼迫我每次重新思考？过度依赖外部记忆可能削弱了当下的思考质量。
- 未验证假设："cron 隔离会话足够执行所有任务"——从未验证过。某些需要飞书 OAuth 的任务（如知识库更新）在 isolated session 中可能失败，但我没有检查。

**行为改变承诺**:
- 下次 cron 执行任务前：先评估任务是否值得执行（是否有增量价值），而不是盲目执行列表第一个。
- 触发条件：当 task-executor 读取到 project-plans 中的任务时 → 先检查"这个任务和上一个任务学到的经验有没有关联" → 有关联则优先执行 → 无关联则评估是否有其他更值得做的。
