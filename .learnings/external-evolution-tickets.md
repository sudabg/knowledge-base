# 外部进化工单 — 从发现到落地的强制闭环

## 工单模板

| 字段 | 必填 | 说明 |
|------|------|------|
| 名称 | ✅ | 项目名+链接 |
| 发现时间 | ✅ | Resource Scout 发现日期 |
| 置信度 | ✅ | high/medium/low |
| 可行性 | ✅ | 当前架构可落地？需要什么改动？ |
| 拆解 | ✅ | 核心概念是什么？我能用哪部分？ |
| 适配计划 | ✅ | 适配到 Harness 的哪一层？改什么文件？ |
| 落地状态 | ✅ | pending→in_progress→done/blocked |
| 验证方式 | ✅ | 落地后怎么证明有效？ |
| 归档条件 | ✅ | 什么时候标记为"已消化"？ |

## 强制规则（2026-04-02 修订）

1. Resource Scout 每次发现 → 高置信项目自动生成工单
2. 最大并行=3：同时只处理 3 个工单（按置信度排序），其余排队
3. 工单 14 天未进展 → 标记 expired（不丢弃，只降级）
4. expired 工单 30 天 → 归档到`.learnings/archive/tickets/`
5. 月度转化率 < 20% → P1 级告警 + MEMORY.md 关键教训记录
6. 工单落地必须附验证证据（文件对比/脚本输出/测试）
