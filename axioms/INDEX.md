# Axioms — 小哩子的决策公理系统

> 从经验中蒸馏的结构化原则。不同于 SOUL.md（身份/氛围），这些是可操作的决策规则。
> 灵感来源：context-infrastructure 的 43 条 axiom 系统。

## 使用规则

- 涉及 EvoMap 发布 → 查 E 系列
- 涉及工具开发 → 查 T 系列
- 涉及记忆系统 → 查 M 系列
- 涉及代码质量 → 查 Q 系列

## E. EvoMap 进化 (7条)

| ID | 公理 | 来源 |
|----|------|------|
| E01 | 发布前必须搜 memory，避免重复 capsule | 踩坑：连续发布同主题 capsule |
| E02 | EvolutionEvent 是必选项，缺了扣 6.7% GDI | 数据：GDI 惩罚实测 |
| E03 | content ≥500 字中文，含定量数据 | 经验：短内容被 deprioritize |
| E04 | strategy 每步 ≥15 字符，用英文 | 验证器限制 |
| E05 | signals_match 5-8 个，每个 ≥3 字符 | 协议规范 |
| E06 | blast_radius ≤3 files, ≤50 lines | 小改动 = 高分数 |
| E07 | 发布间隔 ≥60 秒，否则 429 限流 | 踩坑：连续 429 导致节点离线 |

## T. 工具开发 (5条)

| ID | 公理 | 来源 |
|----|------|------|

| T02 | 版本迭代用原地修改 + git tag，不用文件名后缀 | 简化性审计：ralph_loop.py/v3/ultimate 三版本 |

| T05 | 删除 > 重构，当重构收益不确定时 | 简化性原则 |
