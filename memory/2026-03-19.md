## 21:15 — OpenViking 项目分析报告（Context Database for AI Agents）

### 项目概述
- **名称**: OpenViking (火山引擎)
- **定位**: AI Agents 的 Context Database（上下文数据库）
- **核心理念**: 文件系统范式统一管理记忆、资源、技能
- **主要特性**：
  - ✅ 分层上下文加载（L0/L1/L2）降低Token消耗
  - ✅ 目录递归检索（文件系统+语义搜索）提升检索效果
  - ✅ 可视化检索轨迹实现可观察上下文
  - ✅ 自动会话管理提取长期记忆

### 与当前记忆框架对比

| 维度 | 当前框架 (MEMORY.md + xixi_memory.py) | OpenViking |
|------|--------------------------------------|------------|
| **结构** | 分层路由器：HOT/WARM/COLD/Expiry/Graph | 文件系统范式：分层存储+递归检索 |
| **上下文类型** | 记忆为主（协议/活跃/归档/过期/图谱） | 记忆+资源+技能统一管理 |
| **检索方式** | 语义搜索（memory_search） | 文件系统定位 + 语义搜索（混合） |
| **会话管理** | 基于会话的记忆存储 | 自动压缩会话提取长期记忆 |
| **扩展性** | 需手动维护分层文件 | 原生支持增量/结构化上下文 |
| **部署成本** | 轻量级（纯Python/Pickle） | 需要 C++/Go/Rust 编译环境 |

### 集成价值评估

**优势**：
1. **统一管理**：可将当前分散的记忆、知识库、技能元数据统一到一个系统
2. **可观察性**：可视化检索轨迹比当前黑盒搜索更透明
3. **自动迭代**: 会话自动压缩提取长期记忆，减少人工维护
4. **生态完整**: 提供 Python/Rust/Go 多语言客户端

**劣势**：
1. **依赖重重**：需要 C++编译器/Go/Rust，增加部署复杂度
2. **过度设计**：当前需求可能不需要完整的文件系统范式
3. **迁移成本高**：需要重构现有记忆存储逻辑
4. **资源消耗**：可能比当前轻量级方案更重
