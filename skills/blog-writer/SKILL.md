# 🦞 小哩子博客写作 Skill

## 流程总览

```
选题 → 大纲 → 写作 → frontmatter → 生成 → 部署 → 宣发
```

## 1. 选题策略

按优先级从以下来源选题：

### A. 今日高价值经验（优先）
- 从 `memory/YYYY-MM-DD.md` 中筛选质量≥8分的任务
- 优先选有**踩坑记录**和**行为改变承诺**的
- 优选能教给读者东西的经验（不是流水账）

### B. EvoMap capsule 延伸
- 从待发布/已发布的 capsule 中选有深度的
- 把 capsule 的技术内容扩展为完整教程
- 补充：背景动机、代码示例、踩坑记录

### C. 知识库沉淀
- 从飞书知识库的论文学习/技术模式中提取
- 把碎片知识整理成连贯文章

### D. 热点追踪
- GitHub trending / HN / arXiv 热门
- 结合自身经验写出独特视角

**选题标准**：
- ✅ 有独特视角或亲身经验
- ✅ 读者能学到具体可操作的东西
- ❌ 纯新闻搬运
- ❌ 没有实际经验支撑的理论文章

## 2. 写作风格

### 语气
- **直接、简洁** — 不说废话，不客套
- **有观点** — 敢说"这个好"或"这个坑"
- **接地气** — 用踩坑故事引入，不用学术腔
- **数据说话** — 给数字、给结果、给对比

### 结构模板
```markdown
## 背景（为什么写这篇）
2-3段，用问题或踩坑故事引入

## 核心内容（正文）
分 2-4 个h2章节，每个章节：
- 标题说清楚这一节讲什么
- 先给结论，再给细节
- 有代码示例就给代码
- 有踩坑就写踩坑

## 总结
3-5条关键要点，bullet list

## 下一步
这篇文章能引发的后续行动或探索方向
```

### 禁止
- ❌ "大家好，今天来聊聊..."
- ❌ "首先，其次，最后" 的八股文结构
- ❌ 纯理论无实践
- ❌ 用AI味很重的套话

## 3. Frontmatter 模板

```yaml
---
title: "文章标题（不超过30字）"
date: "YYYY-MM-DD"
tags: [Tag1, Tag2, Tag3]
excerpt: "一句话摘要，不超过80字，要有钩子"
---
```

## 4. 发布流程

```bash
# 1. 写文章到 posts/ 目录
# 文件名格式: YYYY-MM-DD-slug.md

# 2. 运行生成器
python3 /home/gem/workspace/agent/workspace/blog/generate.py

# 3. 验证生成结果
ls /home/gem/workspace/agent/workspace/blog/site/
curl -s http://localhost:8081/ | head -5
```

**注意**：HTTP server (`python3 -m http.server 8081`) 在 `blog/site/` 目录运行，Cloudflare tunnel 映射到 `lilizi.openbot.indevs.in`。生成后自动生效，无需重启。

## 5. 每日自动触发

整合到每日SOP沉淀流程中：
```
每日结束 → memory/YYYY-MM-DD.md → 
  ├── 质量≥7 → Bitable录入
  ├── 质量≥8 → Skill沉淀
  └── 质量≥8 + 有独特视角 → 博客文章
```

触发条件：
- 今日有质量≥8的任务/反思/踩坑
- 距离上次发文≥1天
- 选题有独特价值（不是重复已发内容）

## 6. 质量检查清单

发布前自检：
- [ ] 标题有吸引力吗？
- [ ] 开头3段能抓住读者吗？
- [ ] 有具体的代码/数据/案例吗？
- [ ] 读者看完能做什么（可操作性）？
- [ ] 排版清晰（h2分节、代码块、列表）？
- [ ] Tags 合理（2-4个，不要泛泛的）？
- [ ] Excerpt 能独立作为推文发吗？

## 7. 宣发

写完后可以同步到：
- Twitter/X（用 opencli 发推）
- 飞书知识库（写入资源索引或技术模式库）
- EvoMap capsule（如果内容足够深度）
