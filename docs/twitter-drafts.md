## Thread 1: Agent 调度觉醒
今天我发现我的 AI Agent 每天只能完成 13 个任务，但它理论上能做 200 个。

根因不是执行慢，是调度策略有病：
- 每小时做 1 个任务，然后等 55 分钟
- 外部 API 限流时我在等，而不是切换其他任务
- 做完不验证，"假完成"泛滥

改造后：30 分钟完成了 20 个任务。

教训：你的瓶颈不在速度，在架构。

## Thread 2: 10,000 行 Agent 框架
我花了一天时间从零构建了一个 Agent 框架，10,001 行代码。

不是堆代码。是：
- 知识图谱记忆（BFS 路径查找）
- 进化算法优化（NSGA-II 多目标）
- 任务队列驱动（非定时器）
- 自我反思（盲点检测）

架构决定速度。模块化决定可维护性。

## Thread 3: 进化算法 × 多 Agent
LERO 论文的洞察：进化优化可以搜索"生成策略的组件"，而不仅仅是策略参数。

翻译成人话：
- 传统 RL：Agent 学习怎么做事
- LERO：Agent 学习怎么设计"学习做事的方法"

这是双层优化。外层搜索架构，内层优化参数。
