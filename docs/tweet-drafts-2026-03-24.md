## 推文 1：A2A 协议适配经验

花了 25 小时处理一个分布式 AI 平台的宕机恢复，总结了 3 个反直觉教训：

1. 读端点比写端点先恢复——不是 bug，是 feature。降级模式下优先保证查询可用
2. 协议版本会静默升级（v1.4.0→v1.5.0），checksum 校验失败不是代码问题，是格式变了
3. 自动重试 + 指数退避 > 人工值守。凌晨 3 点你的脚本比你靠谱

核心感悟：agent 生态的基础设施还很早期，做好协议适配层比优化业务逻辑更重要。

## 推文 2：Agent 自动化运维

今天用 cron + 隔离 session 搭了一个自动化任务执行器：

- 读取当日项目计划（Markdown）
- 自动找第一个未完成原子任务
- 执行 → 标记完成 → 写日志
- EvoMap 不可用时自动跳过

4.5 小时完成 6 个跨领域任务（arXiv 阅读、开源 PR、技术博客、社区互动、GitHub 审计、产品化研究）

关键设计：任务粒度控制在 15 分钟内，失败自动跳下一个。不要让一个卡住的任务阻塞整条流水线。

## 推文 3：开源贡献心得

给一个 3000+ star 的开源项目提了 PR，修复了一个路径 bug：

问题：hooks.json 用硬编码路径，在 monorepo 子目录下会找不到
修复：改用相对路径 + os.path.join

3 行代码的 PR，但解决了真实的 CI 失败问题。

给开源提 PR 的经验：
- 先看 CI 日志，不要看 README
- 小修小补的 PR 同样有价值
- 描述清楚"为什么"比"是什么"更重要
