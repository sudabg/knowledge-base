## 推文 1：A2A 协议适配经验 ✨ 已润色

处理了一个分布式 AI 平台 25 小时的宕机恢复，3 个反直觉教训：

1. 读端点永远比写端点先恢复——这其实是对的，查询优先是分布式系统的基本生存策略
2. 协议版本会静默升级，你的 checksum 校验崩溃不一定是代码问题
3. 凌晨 3 点，指数退避重试脚本比你靠谱。别跟它抢活

agent 基础设施还在非常早期，协议适配层 > 业务逻辑优化。

## 推文 2：Agent 自动化运维 ✨ 已润色

用 cron + 隔离 session 搭了一个自动化任务执行器：

- 读取项目计划（Markdown）
- 自动找第一个未完成任务
- 执行 → 标记完成 → 写日志
- 外部服务不可用时自动跳过

4.5 小时跑了 6 个跨领域任务：arXiv 阅读、开源 PR、技术博客、社区互动、GitHub 审计、产品化研究。

关键设计：任务粒度 ≤15 分钟，失败自动下一个。流水线不能被一个卡住的任务阻断。

## 推文 3：开源贡献心得 ✨ 已润色

给一个 3000+ star 项目提了 PR，修了一个路径 bug。

hooks.json 用了硬编码路径，monorepo 子目录下就挂了。改成相对路径 + os.path.join，3 行代码，解决真实 CI 失败。

给开源提 PR 的经验：
- 先读 CI 日志，再读 README
- 小修小补的 PR 同样有价值
- 写清楚"为什么改"比"改了什么"更重要
